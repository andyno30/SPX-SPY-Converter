SPYCONVERTER API / DOCUMENTATION

Start with one request.

The existing conversion response, available through a dedicated authenticated API.

All examples are synthetic. api.spyconverter.com is the proposed hostname; it has not been deployed. Use the local preview origin for testing.
AuthenticationEndpointsExamplesResponseFreshnessErrors & limits

Authentication

Send Authorization: Bearer sc_test_… for synthetic data. Live keys use sc_live_… and remain disabled. Keys are shown once, stored as secure hashes, and scoped to an organization. Do not place API keys in public browser code, URLs, or logs.

All keys share their organization’s limits. Each request checks the subscription, paid period, key revocation, and Business approval. Test API access is a demonstration capability, not a free commercial API tier.

Endpoints

GET/v1/conversions

Returns the original JSON body unchanged. Optional esContract=AUTO or one of ESU26, ESZ26, ESH27, ESM27, ESU27. Expired or unavailable contracts return 503; invalid selections return 400. The ESContracts array identifies currently available selections.

GET/v1/convert?from=SPX&to=SPY&amount=7000

Calculates an individual result from the same snapshot. Supports both directions between instruments within SPX/SPY/ES, QQQ/NQ/NDX, DJI/DIA/YM, RUT/IWM/RTY. No cross-group conversions. Amount must be a decimal from 0 through 10¹². Optional ES contract selection applies here too.

GET/v1/usage

Current plan, quota, used and remaining requests, per-minute limit, and billing-period reset date.

GET/v1/status

Environment and access-gate status. Does not claim every quote is current. Usage and status require authentication and count toward the minute limit, but not the monthly conversion quota.

Request examples

curl "https://api.spyconverter.com/v1/conversions" \
  -H "Authorization: Bearer $SPYCONVERTER_API_KEY"
import os
import requests

response = requests.get(
    "https://api.spyconverter.com/v1/conversions",
    headers={"Authorization": f"Bearer {os.environ['SPYCONVERTER_API_KEY']}"},
    timeout=15,
)
response.raise_for_status()
data = response.json()
print(data["SPX/SPY Ratio"])
const response = await fetch(
  "https://api.spyconverter.com/v1/conversions",
  { headers: { Authorization: `Bearer ${process.env.SPYCONVERTER_API_KEY}` } }
);
if (!response.ok) throw new Error(`API error: ${response.status}`);
const data = await response.json();
console.log(data["SPX/SPY Ratio"]);

Cache and quote freshness

Datetime is the source cache update time. It is not the timestamp of every underlying quote. Only ESQuote includes an upstream timestamp and delay in this existing response.

The source snapshot expires after 120 seconds. Copying it does not extend its lifetime. Failed refreshes keep the last successful snapshot until that limit; stale or missing data returns 503. Customer requests never trigger provider requests.

Response headers provide X-Snapshot-Id, X-Source-Fetched-At, X-Cache-Age-Seconds, and X-Data-Mode without changing the JSON. No real-time, execution, or uptime guarantee is made.

Errors and rate limits

HTTPMeaningAction
400Invalid parameter or contractCorrect the request
401Invalid or revoked keyCheck credentials
403Subscription or approval requiredReview account status
429Minute limit or monthly quotaHonor Retry-After
503Stale, missing, disabled data or backend outageBack off; inspect account/status
{"error":{"code":"rate_limit","message":"Your organization has reached its per-minute limit.","request_id":"…"}}

Developer: 10/minute and 10,000/month. Pro: 30/minute and 100,000/month. Business: 120/minute and 500,000/month. The minute window rolls continuously across all organization keys. Monthly quota resets at the Stripe billing-period boundary, not the calendar month. Monthly quota is reserved when a valid, fresh conversion is admitted. Validation failures, initially stale data and limit rejections use no monthly units; status and usage calls also use none. An admitted request may still count if delivery later fails or the snapshot expires during processing. There are no automatic overages.

Each HTTP attempt is a new request. Client-supplied request IDs cannot bypass accounting. Retries within the backend are metered idempotently.
